# hexmakR v5 library and editor update

Prepared before implementation, 27 October 2026.

## Required result

The v5 named composition is the default: exact package name INSIDE the lower
hex, scientific motif above, family-coloured opaque border, tinted interior,
transparent exterior. The supplied phenoscapR image is the visual reference.
All 45 v5 identities must be available as editable native R drawings and as
original approved assets. The 46 generic icons and existing APIs remain usable.

## Evidence and reconciliation

- hexstickers baseline dc384ed: 41 named/name-free vector sets, Python build
  pipeline, original catalogue and domain palette. README count of 40 is stale.
- hexmakR baseline 661c659: package 0.1.0; ggplot/grid drawing, 46 generic icons,
  19 themes, five Shiny control modules, PNG/SVG export. Current artwork branding
  has been updated but the renderer/editor has not incorporated the v5 library.
- 13 archives inventoried with SHA-256 before extraction. v5: 45 identities,
  six master variants each in PNG/SVG/PDF, five icon sizes: 1,035 originals.
- v4.1 source ZIP matches the corresponding files in the full v4.1 ZIP. Motifs,
  palette, primitives, accessibility and tokens code match v5; v5 changes the
  composition and name placement. v5 is authoritative for current output.
- 12 legacy catalogue names lack an exact v5 entry. hexmakeR -> hexmakR and
  delphyR -> delphyr are recorded explicitly; the other ten remain legacy
  references, not silently relabelled or claimed as approved v5 drawings.
- R 4.6.1 and Cairo are available. Intended bundled fonts are not installed;
  use the bundled font file to outline name glyphs rather than silently
  substitute a device font or change the user's system font configuration.

## Implementation sequence

1. Import complete v5 assets, source, per-identity entry points, metadata,
   font licences and archive provenance under inst/cttir. Keep older-only SVGs
   in a clearly marked reference directory. Validate all import checksums.
2. Load the supplied renderer in a private environment, with no changes to
   working directory, global environment, graphics options or fontconfig.
   Adapt composition to an editable design model; use explicit schema/version,
   identity, mode, layout, label, palette roles and deterministic layer edits.
3. Public R API: catalogue, asset lookup, design creation, grob rendering,
   layer inspection/editing, project JSON roundtrip, R recipe, single and batch
   PNG/SVG/PDF exports. Expose motif-only output separately from framed hexes.
   Keep defaults named/dark, support light and mono and artwork-only exports.
4. Capture native grid geometry into stable numbered layers. Allow manual
   fill/stroke/line-width/opacity, translation, scale, visibility and explicit
   point coordinates. Validate bounds/types and reject unknown JSON fields.
   Save declarative data only; loading a project never evaluates R code.
5. New default Shiny workspace: searchable package selector, preview, mode,
   name, palette roles, motif position/scale, layer inspector, shape controls,
   undo/reset, JSON upload/download and PNG/SVG/PDF/R export. Keep the old
   designer available as a separate workspace. Add browsable gallery and
   original asset access. Errors should be visible, not substitute artwork.
6. Update version, README, NEWS, reference docs and vignette; refresh bundled
   application logo and pkgdown reference sections while retaining themakR.
7. Verification: complete pre-existing suite; new meaningful regression tests
   for registry, all 45 motifs and modes, layer editing, malformed projects,
   save/load equivalence, device cleanup, transparent corners and export
   dimensions; batch generate 45 x 3 x 2 masters and icons; compare reference
   composition and inspect live browser controls, preview and export.
8. Run source build and R CMD check, record exact results and any environment
   limitations. Copy reviewed changes back only after baseline hash comparison
   and preserve a backup of modified files. Verify destination hashes.

## Acceptance criteria

- All 45 entries render; supplied 1,035 assets are unchanged and accessible.
- Named defaults match the reference structure in every mode.
- Geometry remains native vector R; SVG/PDF contain no embedded artwork raster.
- A manual layer change persists through JSON and generated R reproduction.
- Editor preview and downloaded files use the same design/rendering path.
- No global source(), working-directory dependence, silent fallback or evaluated
  uploaded code. Existing API tests pass.
- Package build/check and browser verification results are recorded truthfully.

## Added requirement: project logo shapes

The user subsequently requested pentagonal and square project logos. Add a
shape field to the design schema, a `logo_design()` constructor for project
names, and editor frame selection. Preserve regular pentagon geometry and
square aspect ratio; clip artwork to the selected frame. Both CTTIR motifs
and all 46 generic icons must be available. Test all three shapes through
rendering, layer editing, JSON and exports. CTTIR defaults remain named hexes.

The identities `CTTIR` and `cttiR` differ only in case. To prevent collisions
on macOS and Windows, the organisation's asset folder is `CTTIR-brand`; the
R package retains `cttiR`. `hex_catalog()$asset_dir` records the mapping, and
asset lookup, the gallery and batch rendering use it. Displayed names remain
exact. Original assets were re-imported directly from distinct ZIP entries.
